# BernO
An innovative breath-driven olfactory display system, designed for spatial olfactory interaction in virtual reality environments, releases scents through the airflow generated by the user's natural inhalation.
The Python side reads real-time experiment logs from an Android app via `adb logcat`, computes left/right output levels, and sends commands over serial to an Arduino. The Arduino receives position/speed commands and drives two 4‑wire steppers using `AccelStepper`.

## Contents

- `arduino_stepper_controller.ino`
  - Serial command format: `<pos1> <pos2> <speed>\n`
  - Controls two `AccelStepper::FULL4WIRE` motors
  - Sends back a single line `ok` after each command, used by the Python scripts as an ACK

- `angle_grad.py`
  - “Angle–gradient” mapping: uses the signed angular error between current `yaw` and the `target` direction to compute left/right levels (`lrcheck`), then maps them to motor target positions (`prop2motor`)

- `angle_plume.py`
  - “Angle–plume (pulsed plume)” mapping: generates a time-varying concentration `conc` (`gen_plume`) based on angular offset, then splits to left/right via `plume_lrcheck`

- `line_grad.py`
  - “1D distance–gradient” mapping: computes distance error `abs(sCam - target)` and applies symmetric decay (`discheck`) to both sides

- `line_plume.py`
  - “1D distance–plume (pulsed plume)” mapping: generates `conc` from the 1D distance error and drives both motors symmetrically

- `hybrid_grad.py`
  - “2D target–gradient” mapping: parses `[Pose]` logs to obtain user pose + target coordinates, then computes:
    - `relative_yaw`: signed angle between heading and the vector to the target
    - `relative_dis`: Euclidean distance to the target
  - When close, outputs symmetric intensity; when far, uses angle-based left/right splitting

- `hybrid_plume.py`
  - “2D target–plume (pulsed plume)” mapping: same geometry as `hybrid_grad.py`, but intensity is generated by plume logic

## Requirements

### Python
- Python 3.x
- Packages:
  - `pyserial`
  - `pyyaml`

Install (Windows):
```bash
pip install pyserial pyyaml
```

### Android / ADB
- `adb` installed and available in your PATH
- Android device connected with USB debugging enabled
- The experiment app must output log lines matching the patterns used by the scripts (see “Log formats”)

### Arduino
- Arduino IDE
- Library: `AccelStepper`
- Two 4‑wire stepper motors wired to the pins defined in the sketch

## Configuration (`cfg.yaml`)

All Python scripts expect a `cfg.yaml` in the same directory containing the serial port:

```yaml
com_num: COM3
```

Notes:
- On Windows, ports are typically `COM3`, `COM4`, etc.
- Make sure the port matches the Arduino’s COM port.

## Arduino pins / wiring

`arduino_stepper_controller.ino` defines two sets of 4‑wire pins:

- Motor 1:
  - `A_PLUS_1  = 2`
  - `A_MINUS_1 = 6`
  - `B_PLUS_1  = 4`
  - `B_MINUS_1 = 8`

- Motor 2:
  - `A_PLUS_2  = 3`
  - `A_MINUS_2 = 7`
  - `B_PLUS_2  = 5`
  - `B_MINUS_2 = 9`

Serial baud rate: `115200`

Command protocol:
- Python sends: `"{pos1} {pos2} {speed}\n"`
- Arduino responds: `ok`

## Log formats expected from the Android app

The scripts run `adb logcat -v raw` and parse specific lines using regular expressions. Your app output must include the following tags/fields (exact tag strings matter in some scripts):

### Angle/Line scripts
- Real-time updates:
  - Line contains `"[Trial]"` and includes `yaw=...`
  - `angle_*.py` expects: `trial, target, x, y, z, yaw, unix`
  - `line_*.py` expects additional fields: `sCam=... errS=...`
- Round end:
  - Line contains `"[DistanceTrial] end"` and includes: `targetS=... lastS=... errS=... rt=...`
- Block end:
  - Line contains `"[DistanceTrial] block finished"`

### Hybrid (2D target) scripts
- Pose update:
  - Line contains `"[Pose]"` (the internal regex is case-insensitive and matches `[pose]`)
  - Includes pose + target fields (see `POSE_RE` in the scripts)
- Events:
  - `"[Open]"`, `"[RoundEnd]"`, and end tag `"[GameEnd]"`

## How to run

1. Upload Arduino firmware:
   - Open `arduino_stepper_controller.ino`
   - Install `AccelStepper`
   - Select the correct board and port and upload

2. Create `cfg.yaml` in the same folder as the scripts and set `com_num` to your Arduino port.

3. Verify ADB:
```bash
adb devices
```

4. Run one script (choose one):
```bash
python angle_grad.py
python angle_plume.py
python line_grad.py
python line_plume.py
python hybrid_grad.py
python hybrid_plume.py
```

Runtime behavior:
- Continuously reads logcat and streams motor commands to the Arduino
- On end events, stops and writes a CSV file

# BernO
An innovative breath-driven olfactory display system, designed for spatial olfactory interaction in virtual reality environments, releases scents through the airflow generated by the user's natural inhalation.


The Python side reads real-time logs from the experimental App via adb logcat, calculates the left/right output intensity, and sends the data to the Arduino via the serial port. The Arduino then drives the two stepper motors.

File Description

arduino_stepper_controller.ino

Arduino serial command format: <pos1> <pos2> <speed>\n

Uses AccelStepperto control two 4-wire stepper motors (FULL4WIRE)

Sends back an okline after processing each command for confirmation by the Python side

angle_grad.py

"Angle-Gradient" version: Calculates left/right intensity (lrcheck) based on the angle between the current heading yawand the target direction target, then maps it to the stepper target position (prop2motor)

angle_plume.py

"Angle-Plume (Pulse/Plume)" version: Generates a pulse concentration conc(gen_plume) that varies with time/distance based on the angle difference, then allocates it left/right (plume_lrcheck)

line_grad.py

"Linear Distance-Gradient" version: Calculates left/right same-intensity attenuation (discheck) based on the distance error abs(sCam-target)

line_plume.py

"Linear Distance-Plume (Pulse/Plume)" version: Generates concbased on the linear distance error, with same-intensity output for left/right

hybrid_grad.py

"2D Target-Gradient" version: Parses player position and target position from [Pose]logs, calculates:

relative_yaw: Signed angle between the player's heading and the "vector pointing to the target"

relative_dis: Distance to the target

Same intensity for left/right when very close; allocates intensity based on angle difference when farther away

hybrid_plume.py

"2D Target-Plume (Pulse/Plume)" version: Same geometric logic as hybrid_grad.py, but intensity is generated by plume logic

Hardware/Pins (Arduino)

arduino_stepper_controller.inodefines the pins for two 4-wire stepper motors:

Motor 1:

A_PLUS_1  = 2

A_MINUS_1 = 6

B_PLUS_1  = 4

B_MINUS_1 = 8

Motor 2:

A_PLUS_2  = 3

A_MINUS_2 = 7

B_PLUS_2  = 5

B_MINUS_2 = 9

Serial baud rate: 115200

Command format:

Python sends: "{pos1} {pos2} {speed}\n"

Arduino responds: ok

Log Format (from App's logcat)

Scripts read log lines via adb logcat -v rawand parse key fields using regular expressions. Ensure the App output contains the following snippets (case/prefix must match the scripts):

Real-time frames for angle/linear versions:

Contains "[Trial]"and fields like yaw=...

angle_*.pyparses fields: trial, target, x, y, z, yaw, unix

line_*.pyparses fields: additionally includes sCam=... errS=...

Trial end:

"[DistanceTrial] end"and contains fields: targetS=... lastS=... errS=... rt=...

Block end:

"[DistanceTrial] block finished"

Hybrid (2D target) version:

Real-time frames use "[Pose]"(script internally uses regex $$pose$$, case-insensitive)

Trial events use "[Open]", "[RoundEnd]", end uses "[GameEnd]"

How to Run

Upload to Arduino:

Open arduino_stepper_controller.ino

Install the AccelStepperlibrary

Select the correct board and port, then upload

Prepare cfg.yaml:

Place it in the same directory as the scripts

Set com_numto the Arduino's serial port, e.g., COM3

Connect the Android device and confirm adbis available:

bash
adb devices

Run the desired script from this directory (choose one):

bash
python angle_grad.py
python angle_plume.py
python line_grad.py
python line_plume.py
python hybrid_grad.py
python hybrid_plume.py

Runtime behavior:

Python continuously reads logcat and sends motor target positions to the Arduino

Stops and outputs/saves a CSV upon detecting "end / block finished / GameEnd"

Output Data (CSV)

Scripts generate a CSV file upon exit (filename includes a timestamp), for example:

test1_plume_YYYYMMDD_HHMMSS.csv

test2_con_grad_...csv

test2_plume_...csv

Fields vary by script:

angle/line CSVs: tgt,chosen,err,rtor targetS,lastS,errS,rt

hybrid CSVs: Include trial, chest_*, is_target, target_*, rt, unix, etc.

Safety and Notes

Before starting, it is advisable to zero the motor output (script sends 0 0 800on exit) and ensure the mechanical structure does not jam.

prop2motor()maps an intensity of 0~1 to a maximum target position of ~750; adjust the mapping or add limits if the hardware has a smaller range.

If Arduino does not respond with ok, Python will print timeout/time out; check for serial port conflicts, baud rate, and wiring.
